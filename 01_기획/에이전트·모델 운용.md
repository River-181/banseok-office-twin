# 에이전트·모델 운용

## 역할 분담
- **claude.ai 프로젝트 (이 대화)**: 기획, 질문 정리, 판단이 필요한 논의.
- **Claude Desktop + Filesystem 확장**: 대화하면서 이 폴더의 문서를 직접 읽고 고치기. 스크립트 실행은 못 함.
- **Claude Code (로컬, 이 폴더에서 실행)**: 파일을 직접 읽고 쓰는 실제 제작. `CLAUDE.md`가 자동으로 맥락을 불러와.

## 모델 배치
| 에이전트 | 모델 | 맡는 일 | 왜 이 모델 |
|---|---|---|---|
| 메인 세션 | Sonnet 5 | 지휘, 일반 코딩 | 대부분 작업에 충분하고 저렴 |
| plan-auditor | Opus 5 | 도면·사진 판독, JSON 대조 | 틀리면 전부 틀어지는 구간, 호출 횟수는 적음 |
| geometry-builder | Sonnet 5 | JSON → GLB, 검증 스크립트 | 코드 생성 품질/비용 균형 |
| viewer-builder | Sonnet 5 | three.js 뷰어 | 〃 |
| site-terrain | Sonnet 5 | 지형·주변 건물 데이터 | 〃 |
| scribe | Haiku 4.5 | 세션로그, 결정로그, README | 단순 정리라 제일 싼 모델 |

## 토큰 아끼는 원칙
1. 이미지는 판독 에이전트만, 그것도 필요한 타일 하나만 본다. 나머지는 전부 JSON을 읽는다.
2. 숫자 검증은 LLM이 아니라 스크립트가 한다.
3. 서브에이전트는 결과를 15줄 이내로 요약해서 돌려준다 (메인 컨텍스트 보호).
4. 세션이 끝나면 scribe가 로그를 남기니까, 다음 세션은 README + 최신 세션로그만 읽고 시작한다.
