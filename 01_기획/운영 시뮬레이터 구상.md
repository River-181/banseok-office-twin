# 운영 시뮬레이터 구상

> [!summary]
> 3D 사무실을 **객체(Object) 기반 운영 시뮬레이터**로 키운다. 사람·자리·사물·차량·체납 케이스를 전부 객체로 두고, 시뮬레이션 코어(Python)가 하루를 돌려 이벤트 로그를 만들면 3D 뷰어가 그걸 재생한다. 목표 감성은 타이쿤 + 심즈/림월드.

## 1. 사람의 정의

체납관리단 구조(운영·동행공무원 + 실태확인원)를 그대로 따른다.

| 용어 | 정의 | 예 |
|---|---|---|
| **구성원** | 시뮬레이션 속 모든 사람 에이전트. 직원 + 외부인 | 아래 전부 + 방문 체납자 |
| **직원** | 이 사무실에서 근무하고 급여를 받는 사람 | 공무원, 실태확인원, 관리보조 |
| 공무원 | 국세청 소속. 운영공무원 / 동행공무원 | KG-OP, KOG-D2 |
| 실태확인원 | 기간제 근로자. 전화실태확인원 / 방문실태확인원 | 외전-01, 방문1팀 |
| 관리보조 | 안내·행정 지원 | 관리-01, 02 |
| 외부인 | 직원이 아닌 방문자 (체납자·민원인 등) | 시뮬레이션 전용 |

각 직원은 두 축을 가진다: **사업**(국세 / 국세외수입) × **역할**(운영공무원 / 동행공무원 / 전화실태확인원 / 방문실태확인원 / 관리보조).

## 2. 객체 모델

모든 객체는 `id`, `type`, `state`, 위치(좌석·구역·좌표)를 공통으로 가진다. 도면 JSON의 가구 id가 그대로 객체 id다.

| 객체 | 핵심 속성 | 시뮬레이션에서 하는 일 |
|---|---|---|
| Member | 사업, 역할, 팀, 좌석, 근무시간, 스트레스, 숙련도 | 전화·방문·서류·휴식 |
| Team | 구성원, 담당 권역, 차량 | 방문 일정 |
| Seat / Furniture | 규격(카탈로그), 좌표, 장비 | 점유·이동 대상 |
| Asset | 복합기, 세단기, 정수기, 냉장고, 캐비닛 | 사용 대기열, 고장 |
| Vehicle | 차종, 좌석 5, 배터리 kWh, 주행거리, 충전 상태, 주차면 | 팀 출차·복귀, 충전 |
| ParkingSpot | 위치, 충전기 유무 | 차량 배치 |
| Case (체납 건) | 사업, 체납액, 유형, 연락 이력, 주소 권역 | 전화·콜백·방문의 대상, 군집 분석 |
| Event | 시각, 주체, 행동, 결과 | 뷰어 재생·KPI 원천 |

### 차량 (현재 보유)
| 차종 | 대수 | 구동 | 좌석 |
|---|---|---|---|
| 기아 EV6 | 3 | 전기 | 5 |
| 현대 코나 일렉트릭 | 3 | 전기 | 5 |

트림(배터리 용량)과 주차장 위치는 미정이라 `org.json`에 빈칸으로 둔다.

### 시뮬레이션 지표 (예정)
전화원 시간당 통화 가능 수, 연결률, 콜백 비율, 통화당 소요시간 / 방문 1건 소요시간·이동거리·차량 전력 사용 / 직원 스트레스(업무량·민원 강도·휴식으로 증감) / 체납 유형별 군집(생계곤란형, 일시 자금부족형, 고의 회피형 등) / 관리보조 업무량.

## 3. 아키텍처 선택지

| 안 | 구성 | 트레이드오프 |
|---|---|---|
| **A (추천)** | 코어: Python(SimPy 이산사건) → 이벤트 로그 / 화면: 지금의 three.js 웹뷰어가 재생 | 지금 파이프라인 그대로 확장, River 주 언어, 링크 공유 / 심즈급 그래픽은 한계 |
| B | Godot 4로 전환 (코어+화면 한 엔진) | 캐릭터·길찾기·UI가 기본 제공, 웹 export 가능 / 새 도구 학습 |
| C | Unity (카탈로그에 공식 플러그인 있음) | 에셋(차·캐릭터) 풍부 / 무겁고 C#, 파이프라인 이원화 |

A로 가도 데이터(JSON)가 엔진 중립이라, 그래픽 단계에서 B나 C로 옮길 수 있다.
